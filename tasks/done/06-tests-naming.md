  - 주의사항: 이전 단계 완료 후 최신 develop 기반

### 2. 현재 테스트 구조 분석
- [ ] **테스트 디렉토리 구조 확인**
  - `tests/` 및 `testdata/` 디렉토리 내용 분석
  - 완료 기준: 현재 테스트 조직 구조 문서화
  - 주의사항: integration, unit, contract, e2e 등 하위 구조 파악

- [ ] **네이밍 컨벤션 결정**
  - `tests/` vs `test/` 네이밍 결정
  - 완료 기준: 프로젝트 표준 네이밍 컨벤션 확정
  - 주의사항: Go 커뮤니티 관례 및 팀 선호도 고려

### 3. 테스트 디렉토리 이동 (선택사항)
- [ ] **tests → test 리네이밍 검토**
  - 현재 `tests/`를 `test/`로 변경할지 결정
  - 완료 기준: 리네이밍 여부 최종 결정
  - 주의사항: 기존 관례 유지 vs 표준 준수 간 균형

- [ ] **디렉토리 이동 실행** (`git mv tests test`)
  - 결정된 경우에만 디렉토리 이름 변경
  - 완료 기준: 테스트 디렉토리 리네이밍 완료
  - 주의사항: Git 히스토리 보존 및 하위 구조 유지

### 4. 하위 디렉토리 구조 정리
- [ ] **하위 구조 일관성 확인**
  - integration, unit, contract, e2e 등의 명명 일관성 확인
  - 완료 기준: 테스트 타입별 디렉토리명 표준화
  - 주의사항: 기존 CI/CD 스크립트와의 호환성 유지

- [ ] **mocks 디렉토리 정리**
  - `tests/mocks/` 위치 및 구조 최적화
  - 완료 기준: 모의 객체 조직 구조 개선
  - 주의사항: 생성된 mocks와 수동 mocks 구분

### 5. 경로 참조 업데이트
- [ ] **CI/CD 스크립트 업데이트**
  - GitHub Actions 워크플로우의 테스트 경로 업데이트
  - 완료 기준: 모든 CI 스크립트 경로 변경
  - 주의사항: 테스트 실행 명령어 및 커버리지 수집 경로

- [ ] **Makefile 업데이트**
  - 테스트 관련 make 타겟의 경로 업데이트
  - 완료 기준: `make test-*` 타겟들 정상 동작
  - 주의사항: integration, unit, e2e 테스트 타겟 확인

- [ ] **문서 경로 업데이트**
  - `grep -RIl "\btests/\b" . | xargs -I{} sed -i '' -e 's|tests/|test/|g' {}`
  - 모든 문서의 테스트 경로 참조 업데이트
  - 완료 기준: 문서 내 경로 참조 일관성 확보
  - 주의사항: README.md 및 개발 가이드 문서

### 6. 스크립트 경로 업데이트
- [ ] **스크립트 파일 업데이트** (`scripts/` 디렉토리)
  - 테스트 실행 스크립트의 경로 업데이트
  - 완료 기준: 모든 스크립트 정상 동작
  - 주의사항: test-coverage.sh, run-all-tests.sh 등

- [ ] **설정 파일 업데이트**
  - VS Code, GoLand 등 IDE 설정 파일 경로 업데이트
  - 완료 기준: IDE 테스트 실행 환경 정상 동작
  - 주의사항: .vscode/settings.json 등

### 7. 테스트 실행 환경 검증
- [ ] **로컬 테스트 실행**
  - 변경된 구조에서 로컬 테스트 정상 실행 확인
  - 완료 기준: `go test ./...` 성공
  - 주의사항: 경로 의존적인 테스트 케이스 확인

- [ ] **통합 테스트 실행**
  - 테스트 스위트별 개별 실행 확인
  - 완료 기준: unit, integration, e2e 테스트 각각 성공
  - 주의사항: 테스트 데이터 파일 경로 의존성

### 8. 테스트 데이터 정리
- [ ] **testdata 디렉토리 정리**

  - 주의사항: fixtures, mock 데이터 파일 경로 확인
